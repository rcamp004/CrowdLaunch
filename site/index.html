How the crowd estimate works

Each GitHub account gets one equally weighted forecast per question. The latest valid submission observed before the deadline counts. These are self-selected accounts, not verified independent experts. A range shows disagreement, not a confidence interval.

For each contributor who opts into loss estimates: conditional expected loss fraction = total loss probability + partial loss probability × partial severity. We average those individual results. Multiplying each by that contributor’s liftoff probability gives the expected physical payload loss during the specified interval. A postponement can move exposure to a later interval; it does not eliminate eventual mission risk.

Questions have fixed UTC intervals and close before that interval starts. A retargeted launch needs a new question. Source-backed outcomes can later score liftoff forecasts with the Brier score (lower is better). No skill weighting is applied yet.

To revise a forecast, create a new submission before the deadline. Editing after the deadline cannot replace an already recorded version. Maintainers can exclude spam or invalid contributions using the crowd-exclude label. Reasoning, usernames, submissions and snapshots are public; never include confidential or personal information.
